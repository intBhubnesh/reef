# Reef Stage 2 (motion and presence) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Reef's notch feel alive: a per-state animated agent character, a distinct measured transition for every event, and the expanded panel re-laid out to the measured reference.

**Architecture:** All timing and phase logic becomes pure, testable code in `ReefCore` (`Motion` constants, `SpriteAnimator`, `NotchTransition`, `UsageSnapshot`); `ReefApp` only renders it. The notch window is sized to the target plus overshoot headroom and never animated itself, so the spring runs on the drawn shape and the bounce cannot clip.

**Tech Stack:** Swift 5 mode on the Swift 6.2 toolchain, SwiftPM only, SwiftUI (`TimelineView`, `matchedGeometryEffect`, `.spring(response:dampingFraction:)`), AppKit `NSPanel`, no third-party packages.

**Spec:** `docs/superpowers/specs/2026-10-31-reef-stage2-design.md`

**Measurements (the contract):** `/Users/mint/Code/rea/_reference/vibe-island/motion/MOTION-SPEC.md` (animation table, rows cited as `M<row>`) and `.../LAYOUT-SPEC.md` (sections cited as `L<section>`).

## Global Constraints

- macOS 14.0+, SwiftPM only, no third-party dependencies, Swift 5 language mode; `swift test` must stay green after every task.
- Every measured number lives as a named constant in `Sources/ReefCore/Motion/Motion.swift` with a comment citing its MOTION-SPEC row or LAYOUT-SPEC section. No magic numbers in views.
- No animation may delay or swallow a decision: approval buttons are hit-testable from the first frame of an expansion.
- Per-frame work happens only in leaf views driven by `TimelineView`, never in `AppState` and never on a published property.
- Reef's character glyph is original artwork designed for this project. Do not reproduce the reference app's sprite art.
- `prefers-reduced-motion` (`NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`) freezes stepped animation and replaces springs with 120 ms fades.
- Status-line shim installs only when Claude Code's `statusLine` slot is empty; an occupied slot is never modified.
- All 14 Stage 1 acceptance items in `docs/acceptance-2026-10-28.md` must still hold.

## Review Focus

1. A session whose status flips fast (PreToolUse → PostToolUse repeatedly) resets its phase origin each time; the sprite must keep stepping smoothly rather than freezing on frame 0 (Task 3).
2. Two sessions entering the same status in the same tick must animate visibly out of phase, not in lockstep (Task 2).
3. `rl.json` absent, malformed, or older than 10 minutes: the header degrades to the session count or a grey value, never crashes and never shows stale numbers as live (Task 8).
4. A completion peek arriving while a request is still pending must not collapse or replace the blocking panel (Task 4).
5. Panel content taller than the available screen (many sessions plus subagents) must scroll inside a window that still fits on screen, including the overshoot headroom (Task 7).

### Task 2: Sprite animator

**Files:**
- Create: `Sources/ReefCore/Motion/SpriteAnimator.swift`
- Test: `Tests/ReefCoreTests/SpriteAnimatorTests.swift`

**Interfaces:**
- Consumes: `Motion` (Task 1), `SessionStatus` (existing).
- Produces: `public struct SpriteFrame: Equatable { public let bodyFrame: Int; public let eyesOpen: Bool; public let glyph: Glyph?; public let glyphRaised: Bool; public let cursorOn: Bool; public enum Glyph: Equatable { case question, cursor } }`
- Produces: `public enum SpriteAnimator { public static func frame(status: SessionStatus, elapsed: TimeInterval, seed: UInt64, reduceMotion: Bool = false) -> SpriteFrame }`
- Rules: working family (`idle, working, runningTool, compacting`) → `bodyFrame = Int(elapsed / Motion.spriteFramePeriod) % Motion.spriteCycleFrames`, `eyesOpen = true`, no glyph. Waiting family (`waitingForApproval, waitingForQuestion, waitingForPlan`) → `glyph = .question`; `glyphRaised` toggles with period `bobUp + bobDown`, raised for the first `bobUp`; `eyesOpen` flips on a deterministic schedule derived from `seed` with a median gap of `waitEyeMedianGap` (use a seeded SplitMix64 over successive gaps in 0.08…0.38 s, so two different seeds diverge). `.done` → `glyph = .cursor`; `eyesOpen = false` for `blinkClosed` at the start of each `blinkPeriod`; `cursorOn` true for `cursorOn` then false for `cursorOff`, with the first on-phase starting at `cursorFirstOn`. `.failed` → `bodyFrame 0`, `eyesOpen = false`, no glyph. `reduceMotion` → `bodyFrame 0`, `eyesOpen = true`, glyph present for the waiting and done families, `glyphRaised = false`, `cursorOn = true`.
